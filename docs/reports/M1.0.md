  每次迁移及会话回填都在事务内完成；迁移失败回滚，较新版本拒绝降级。
- 新增 `sessions`、`ingest_runs` 与 `events_fts`。索引覆盖已有数据，三个触发器同步
  INSERT / UPDATE / DELETE。新增可空 `events.source_id`，保留旧记录 ID。
- `db.py` 提供批量幂等写入、JSON metadata 局部更新、会话 upsert、游标和运行记录接口。
  所有新写入入口继续执行脱敏；局部更新不会覆盖其他调用方刚写入的字段。
- `collectors/base.py` 定义 `Context`、`CollectResult` 和后续采集器的 `Collector` 协议。
  现有调度使用 Context 和 CollectResult，CLI 保留原统计字段并添加 status / warning_count。
- 采集每 500 条完整源记录提交事件和精确游标，失败只回滚当前批，保留已提交批次。
  继续处理不完整尾行、文件重写、同长度改写和跨运行去重。
- `queries.py` 统一提供事件、会话、收藏、全文搜索、域名统计、项目时长、来源状态查询。
  Codex history 去重查询也迁入查询层，采集器不再直接写 SQL。
- FTS5 trigram 支持三字及以上中文子串；短查询走转义后的 LIKE。
  搜索输入按字面量处理，返回高亮片段；支持来源过滤。
- `timeutils.day_range` 将本地日历日转换为半开 UTC 区间，覆盖夏令时 23 / 25 小时日期。
  项目时长按计划规定的 15 分钟连续间隔、每段 2 分钟、5 分钟取整规则计算。
- `runtime.py` 提供 `run/collect.lock` 文件锁和私有、脱敏的按日日志。
  `collect` 全程持锁；竞争锁的 CLI 进程打印一行提示并以退出码 0 结束。
  后续 build-daily 可复用同一个锁，当前未实现 build-daily。
- 每个来源独立记录运行结果；部分失败与整体失败分开处理；一个来源失败仍尝试其他来源。
  未正常完成的运行保留 failed 状态和空 finished_at，避免误报成功。
- 新增 `noesis stats`、`noesis search` 用户入口；只读打开数据库，不隐式执行迁移。
- `doctor` 检查 SQLite 版本及实际 FTS5/trigram 可用性，并检查新增表。
- 统一项目名入口 `resolve_project`；目前仍返回 cwd 最后一级目录名，M2 再实现仓库解析。

## 与原文、现有代码的兼容决定

1. 代码目录按实际 `~/Desktop/noesis`，数据目录仍为 `~/NOESIS`。
2. 沿用 M0 数据字段、UTC 微秒格式、哈希 cursor key 和 JSON cursor value，未改为明文路径键。
3. M0 没有保存 source_id，因此新增可空字段；旧事件查询使用存储 ID，不伪造原始身份。
4. 保留已有完整前缀指纹校验，未采用“mtime / size 相同就不打开”的优化，以保留已经验证的
   同长度改写检测能力；当前仍有与历史文件体积相关的读取成本。
5. 原 CLI skipped 是过滤行数；CollectResult / ingest_runs.skipped 是重复事件数，
   对应 CLI duplicates。README 和 FORMAT_NOTES 已明确两者，避免改变旧字段含义。
6. 查询层的事件区间使用 `[start, end)`；get_sessions 返回与该区间重叠的会话。
   get_session_events 支持 sessions.id，也支持原始 session_id 加可选 source 消除歧义。
7. stats 的“今天新增”按 created_at 统计入库时间；回填旧消息会计入今天新增。
8. 截断字符上限限制保留的正文，末尾说明额外附加；原有已入库正文没有被批量改写。

`docs/FORMAT_NOTES.md` 已增加 M1.0 更新说明；没有修改既有本机格式调研结论。

## 已知边界与下一步

- 本次完成的是 M1.0。旧版 M1 已存在，不等于新版 M1.1 / M1.2 的增强验收已经通过。
- Collector 协议预留 backfill / dry_run；现有 CLI 仍使用 --replay。
  新版 --backfill / --dry-run 的采集行为和适配留给 M1.1 / M1.2，不宣称已经实现。
- 会话表当前从已保存的事件派生；首条用户消息前 60 字作为标题。
  无可展示消息的空会话不在该表；summary 标题和 session_meta 空会话待采集器增强。
- Claude Code 多行 assistant 合并、命令保留、工具参数摘要，以及 Codex 新版主通道优先、
  history 的 ±5 秒匹配等差异，仍需下一里程碑实现，并设计旧事件身份和计数的兼容迁移。
- 源文件读取期间如较早批次已提交，后续批次失败不会撤销此前数据；下次按游标和指纹恢复。
  若文件被原地重写，沿用已有策略重读去重，不自动删除历史事件。
- 会话派生目前按来源重算，规模扩大后可按受影响会话缩小范围。
- 项目时长严格执行计划算法：只有一个事件时的 2 分钟会取整为 0 分钟；不是精确工时。
- 浏览历史、截图/OCR、每日 Markdown 与定时任务尚未实现；对应查询接口仅由合成数据验证。
- 本次不运行网络请求、不推送 Git、不安装后台任务、不修改系统权限。
