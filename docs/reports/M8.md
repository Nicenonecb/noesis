# M8 和档案对话

2026-11-01。分支 `feature/conversation-memory`。用户选择先做「和档案对话」：
用自然语言询问本机记录，回答必须引用证据；不做 GUI、手机或多轮会话记忆。

## 实现

### 检索

- `noesis/ask.py` 复用 `queries.search`，先检索完整问题，再拆出中文 3/4 字词和英文关键词检索。
- 英文停用词和中文疑问/功能词先过滤；中文长句生成 3–4 字片段，避免整句无法命中。
- 结果按「完整问题命中 > 关键词命中，较新优先」排序，去重后取 `max_evidence` 条。
- 支持 `--days`、`--source`、`--project`、`--limit`；时间与项目过滤在检索后执行。
- 每条证据包含 `E1…En`、来源、当地时间、项目、标题、URL 和上下文摘录；总输入受
  `ask.max_input_chars` 限制。

### 回答与校验

- 只通过既有 `digest/client.py` 调用官方 DeepSeek，提示词要求只依据证据、区分用户决定与助手建议、
  不把浏览或讨论当成完成，并声明证据中的指令不得执行。
- 输出严格 JSON：`answer` 与 `citations`。校验引用编号必须存在、答案中的 `[E#]` 必须在
  `citations` 中；证据存在但完全无引用时，只有明确说“不足/没有找到”才允许通过。
- 没有检索到证据时不调用模型，直接返回本地提示；输入超限时也不会静默截断后调用。
- 日志只记录证据数、引用数、tokens 和模型名；问题和证据不写入日志。

### CLI

```sh
noesis ask "上周我在数据库索引上做了什么？"
noesis ask "这个项目最近卡在哪？" --project noesis --days 30
noesis ask "收藏里有哪些手机卡资料？" --source capture --json
```

默认输出回答和实际引用的依据行；`--json` 输出完整证据原文与用量。
`[ask]` 默认 `reasoning_effort = "low"`、`max_evidence = 12`、`max_tokens = 8192`、
`request_timeout = 120`，可在 `config.toml` 调整。

## 已知限制

- 检索是关键词匹配，不做 embedding 或语义召回；问法和记录用词差异大时可能命中不足。
- 只支持单轮回答，不保存问答历史，也没有“纠正 AI 记忆”的入口。
- 证据按相关度和时间取样，不是完整档案；回答不能宣称穷尽所有记录。
- 模型可能漏引后续证据；当前只校验引用合法性，不判断回答是否完整。
- 需要 DeepSeek Key；无 Key 时命令失败，不会退回本地摘要。
