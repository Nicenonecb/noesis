# M9 DSH 会话采集

2026-11-02。分支 `feature/dsh-collector`。把 DeepSeek Harness（DSH）的本地会话加入
Claude Code、Codex 之外的第三条对话来源，日报、搜索和晨报按同一套事件模型处理。

## DSH 存储格式

- 路径：`~/.dsh/sessions/<workspace>/session-<uuid>/session.v4.jsonl.zstd`。
- 每行一个 JSON 事件；首行 `session` 含 `id`、`createdAt`、`cwd`；后续事件含 `seq`、`time`（毫秒）
  和 `data`。
- 只采集 `user/message` 中 `source.kind == "user"` 的文本，以及 `assistant/message` 中
  `type == "text"` 的文本；跳过 `reasoning`、`tool-call`、工具结果、系统提示、时间/运行时注入、
  技能目录和审批消息。`session/title` 用作会话标题。
- 文件是 zstd 压缩的 JSONL；本机通过 `zstd -dc` 解压，不引入 Python 依赖。

## 实现

- 迁移 `v004`：SQLite 的 `CHECK` 约束不能直接修改，重建 `events` 与 `sessions` 表，
  加入 `dsh` 来源；保留原行、索引、FTS 触发器和 FTS 内容，迁移后执行 `rebuild`。
- `noesis/collectors/dsh.py`：遍历会话文件，解析会话元数据、用户/助手消息和标题；
  用 `session:role:message_id` 生成稳定 ID，重复采集按主键去重。
- 以文件大小 + `mtime_ns` 作为游标；文件未变化时跳过，追加后整文件重读并按事件 ID 去重。
  `--replay` 强制重读且不覆盖游标；`--backfill` 按事件时间过滤。
- `db.record_session_hint` 与 `refresh_sessions('dsh')` 写入会话标题、项目、起止时间和消息数。
- `queries`、日报、晨报来源标签加入 `DSH`；`collect --source dsh`、`search --source dsh` 可用。
- `noesis doctor` 检查 DSH 目录、会话文件和 `zstd` 是否可用。

## 已知限制

- 只支持当前 `session.v4.jsonl.zstd` 格式；DSH 升级格式后需要适配。
- 需要 `zstd` 命令；缺失时采集失败并在 `doctor` 中报告，不会静默跳过。
- 只保留用户和助手的纯文本：图片、工具调用、工具结果、推理和系统注入不进入事件库。
- 正在写入的会话文件可能解压失败或只包含部分消息，下一次采集会重试并去重。
- 文件级游标不是行级 checkpoint；追加后重读整个文件，单文件较大时成本随之增加。
