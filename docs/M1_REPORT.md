# NOESIS · 求是 M1 验收报告

日期：2026-10-25（Asia/Shanghai）。

## 交付

- `noesis collect`：手动执行 Claude Code / Codex 增量采集，支持来源选择和 `--replay` 回填。
- Claude Code：顶层类型和角色联合校验；默认跳过元消息、sidechain/subagents；
  提取可展示正文，排除工具结果、thinking、图片与请求缓存。工具元信息只保存名称。
- Codex：支持 response_item.message、item_completed 的 UserMessage/AgentMessage、
  旧版 user_message/agent_message；保留进度与最终回复，过滤 reasoning、工具和配置事件。
- 从 session_meta/turn_context 跟踪会话、回合及 cwd；不采集环境或账户配置。
- 对已知 AGENTS、环境、Page、system-reminder 和本地命令包装做定界过滤，保留混合消息中的真实输入。
- 按会话、回合、角色、正文摘要与通道出现序号配对镜像；消息 ID 用于跳过同通道重放。
  正常输入不因 client_authored=false 被丢弃。
- Codex history 作为补充来源，按会话、正文摘要、UTC 秒及出现次数与 session 记录对账。
  后到达的 session 可以替换已采集的 history 副本。
- 二进制偏移、完整行处理、完整前缀指纹校验；每文件事件/游标共用事务。
- 先脱敏后截断；游标仅保存上下文和摘要，不保存对话正文或工具参数。

## 已知边界

- 这是手动采集命令，没有安装定时任务、截图/OCR 或浏览历史采集。
- 同回合跨通道同正文按第 N 次出现配对。若某个通道缺失中间消息且另一个通道独立重复同句，
  仅靠现有字段不能保证完全消歧；单通道重复输入会保留。
- history 只做同秒精确配对；不同秒的副本可能保留。不会用全局正文去重吞掉用户重复输入。
- 旧版 Codex 格式仅通过合成样本验证；本机已观察到的新格式通过真实数据验收。
- 每次校验已消费前缀需要读取旧字节；解析是增量的，磁盘 I/O 不是常数成本。
- 轮换/重写后按稳定身份去重并补入新事件，不自动删除或覆盖历史已采集事件。
- 未知类型会跳过并报位置；更新解析器后通过 `--replay` 回填，正常游标保持不变。
- 正则脱敏仍不能保证识别任意自由文本秘密；数据目录仅保存在本机。
